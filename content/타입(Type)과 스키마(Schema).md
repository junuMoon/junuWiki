TypeScript에서 타입과 스키마는 비슷해 보이지만 역할이 다르다.

- 타입(type)은 코드 안에서 "이 값은 이런 모양이어야 한다"라고 표현하는 약속이다.
- 스키마(schema)는 실제 데이터가 그 약속을 지키는지 검사하는 규칙이다.

가장 중요한 차이는 **타입은 주로 컴파일 시점에 작동하고, 스키마는 런타임에도 작동한다는 점**이다.

## 타입

타입은 개발자가 코드를 안전하게 작성하도록 도와주는 도구다. 에디터 자동완성, 정적 분석, 리팩터링 안정성에 큰 도움이 된다.

```ts
type User = {
  name: string
  age: number
}

const user: User = {
  name: "junu",
  age: 20,
}
```

위 코드에서 TypeScript는 `name`이 문자열인지, `age`가 숫자인지 검사한다.  
하지만 이 검사는 개발 중과 빌드 과정에서 주로 이루어진다.

즉, 타입은 다음 질문에 답한다.

- 이 변수는 어떤 값을 가져야 하는가?
- 이 함수는 어떤 인자를 받고 무엇을 반환하는가?
- 이 객체는 어떤 속성을 가져야 하는가?

## 스키마

스키마는 실제 들어온 데이터를 검증하기 위한 규칙이다. 특히 API 응답, 사용자 입력, JSON 파일, 폼 데이터처럼 **외부에서 들어오는 값**을 다룰 때 중요하다.

TypeScript 프로젝트에서는 `zod`, `valibot`, `yup` 같은 라이브러리로 스키마를 자주 만든다. 아래는 `zod` 예시다.

```ts
import { z } from "zod"

const UserSchema = z.object({
  name: z.string(),
  age: z.number(),
})
```

이 스키마는 실행 중에도 실제 값을 검사할 수 있다.

```ts
const result = UserSchema.safeParse({
  name: "junu",
  age: "20",
})

console.log(result.success) // false
```

여기서 `age`는 문자열이므로 검증에 실패한다.  
즉, 스키마는 다음 질문에 답한다.

- 지금 들어온 데이터가 정말 올바른가?
- 잘못된 값은 어디가 문제인가?
- 필요한 경우 이 값을 안전하게 변환할 수 있는가?

## 왜 타입만으로는 부족한가

TypeScript의 타입은 강력하지만, 실행 후에는 사라진다.  
그래서 외부에서 들어온 데이터는 타입만으로 완전히 보호할 수 없다.

```ts
type User = {
  name: string
  age: number
}

const data = JSON.parse('{"name":"junu","age":"20"}')
```

이 `data`는 런타임에 만들어진 값이다. TypeScript는 이 값이 정말 `User`인지 자동으로 보장하지 못한다.  
겉보기에는 비슷해도 `age`는 숫자가 아니라 문자열이다.

이때 필요한 것이 스키마다.

## 타입과 스키마를 함께 쓰는 방식

실무에서는 둘 중 하나만 쓰기보다 함께 쓴다.

- 타입은 코드 내부 구조를 설명한다.
- 스키마는 코드 바깥에서 들어오는 데이터를 검증한다.

예를 들면 다음과 같다.

```ts
import { z } from "zod"

const UserSchema = z.object({
  name: z.string(),
  age: z.number(),
})

type User = z.infer<typeof UserSchema>

function introduce(user: User) {
  return `${user.name} is ${user.age} years old.`
}
```

이 패턴의 장점은 다음과 같다.

- 스키마로 실제 데이터를 검증할 수 있다.
- 타입을 따로 반복해서 쓰지 않아도 된다.
- 스키마와 타입의 모양이 어긋날 가능성을 줄일 수 있다.

## 언제 타입을 쓰고 언제 스키마를 쓰는가

타입이 특히 중요한 경우:

- 함수 인자와 반환값을 명확히 하고 싶을 때
- 객체 구조를 코드 수준에서 설명하고 싶을 때
- 자동완성과 정적 분석의 도움을 받고 싶을 때
- [[제네릭 타입(Generic Type)]]처럼 타입 시스템 자체를 활용하고 싶을 때

스키마가 특히 중요한 경우:

- API 요청과 응답을 검증할 때
- 사용자 입력을 검사할 때
- `localStorage`, 파일, JSON 같은 외부 데이터를 읽을 때
- 신뢰할 수 없는 데이터를 안전하게 처리해야 할 때

## 한 문장 요약

- 타입은 **코드 관점의 약속**이다.
- 스키마는 **데이터 관점의 검증 규칙**이다.

TypeScript를 배울 때는 둘을 이렇게 구분하면 이해가 쉽다.

- 타입: "이 값은 이런 모양이어야 해"
- 스키마: "정말 그런 모양인지 지금 확인해보자"
